1. INTRODUCCIÓN
OmniMerge es una plataforma web diseñada para permitir que los usuarios creen, estructuren, organicen, compartan y reutilicen información sobre entidades completamente personalizables.
La principal característica del sistema es que no impone una estructura fija sobre lo que debe representar una entidad. Una entidad puede ser un personaje, país, animal, objeto, planeta, vehículo, ciudad, elemento, organización, concepto abstracto o cualquier otro elemento que el usuario desee modelar.
El principio fundamental de OmniMerge puede resumirse de la siguiente manera:
La plataforma proporciona la infraestructura, pero el usuario define la estructura de sus datos.
Por ejemplo, una entidad denominada “Naruto Uzumaki” podría tener características como:
Entidad:
Naruto Uzumaki

Tipo:
Personaje

Características:
- Anime: Naruto
- Elemento: Viento
- Aldea: Konoha
- Poder: 92
- Puede volar: No

Mientras que otra entidad completamente diferente podría ser:
Entidad:
Perú

Tipo:
País

Características:
- Continente: América
- Capital: Lima
- Idioma: Español
- Moneda: Sol
- Color representativo: Rojo

Ambas pueden coexistir utilizando exactamente el mismo sistema debido a que los atributos son definidos dinámicamente por los usuarios.
Esta flexibilidad convierte a OmniMerge no solamente en un creador de personajes, sino en una plataforma general de modelado de entidades. El README actual del proyecto define precisamente esta orientación y señala que la Biblioteca constituye la base para futuros módulos como Universos, Torneos, Simulaciones y Rankings.

2. PROBLEMA QUE BUSCA RESOLVER
Muchas herramientas existentes para creación de personajes, fichas, colecciones o sistemas de simulación están diseñadas alrededor de estructuras rígidas.
Es común encontrar aplicaciones donde todos los elementos deben contener campos previamente establecidos, por ejemplo:
Nombre
Edad
Género
Altura
Peso
Raza
Poder

Este enfoque presenta diferentes limitaciones.
Entre ellas se encuentran:
Dependencia de formularios predefinidos.
Imposibilidad de representar objetos de categorías completamente diferentes.
Falta de atributos creados por el propio usuario.
Dificultad para reutilizar características.
Falta de catálogos dinámicos.
Escasa capacidad de selección múltiple.
Poca flexibilidad para relaciones jerárquicas.
Dificultad para agrupar entidades.
Poca reutilización de información entre usuarios.
Falta de preparación para futuros sistemas de interacción o simulación.
OmniMerge busca solucionar este problema mediante una arquitectura donde las entidades no poseen directamente una lista rígida de campos.
En su lugar:
Entidad
   ↓
Atributos seleccionados
   ↓
Valores

De esta manera cada usuario puede construir su propio esquema.

3. OBJETIVO GENERAL
Desarrollar una plataforma web modular que permita crear, administrar, organizar, publicar y reutilizar entidades personalizables mediante atributos dinámicos y catálogos, estableciendo una base escalable para futuros módulos de universos, torneos, simulaciones y rankings.

4. OBJETIVOS ESPECÍFICOS
Los principales objetivos del proyecto son:
Permitir el registro y autenticación segura de usuarios.
Proporcionar una Biblioteca personal para almacenar los recursos creados por cada usuario.
Permitir la creación de Tipos de Entidad para clasificar los diferentes elementos.
Permitir la creación de Entidades completamente personalizables.
Implementar Atributos dinámicos con diferentes tipos de datos.
Permitir que determinados Atributos utilicen Catálogos de valores.
Incorporar valores de Catálogo con imágenes, iconos, colores y jerarquías.
Permitir que una Entidad utilice diferentes Atributos y valores.
Permitir selección múltiple cuando la definición del Atributo lo permita.
Organizar Atributos mediante Grupos.
Organizar Entidades mediante Colecciones.
Implementar visibilidad privada, pública y no listada.
Crear un módulo de Comunidad donde los usuarios puedan descubrir recursos públicos.
Permitir que los recursos compartidos puedan copiarse a otra Biblioteca sin modificar el original.
Registrar la procedencia de los recursos copiados.
Preparar las Entidades para su futura utilización en Universos y Torneos.
Diseñar una arquitectura suficientemente modular para incorporar nuevos subsistemas sin reconstruir la Biblioteca.

ENT000003
...

65. CONCLUSIONES
OmniMerge ha evolucionado desde una aplicación CRUD básica hacia una plataforma de modelado dinámico con una arquitectura preparada para crecer.
La decisión técnica más importante del sistema es separar las Entidades de sus características.
En lugar de utilizar una estructura rígida:
Entity
├── age
├── power
├── anime
├── country
└── color

se utiliza:
Entity
   │
   ├── EntityAttribute
   │        │
   │        └── Attribute
   │
   └── EntityAttributeValue
            │
            └── AttributeOption

Esto permite que la plataforma pueda representar prácticamente cualquier tipo de elemento sin modificar permanentemente la tabla de Entidades.
Los Catálogos añaden reutilización y consistencia, los Grupos permiten organización visual, las Colecciones permiten organización de Entidades y la Comunidad introduce un mecanismo de intercambio mediante copias independientes.
La arquitectura actual proporciona así la base necesaria para que las Entidades puedan convertirse posteriormente en participantes de sistemas más complejos.
La evolución natural del proyecto es:
CREAR
   ↓
ORGANIZAR
   ↓
COMPARTIR
   ↓
REUTILIZAR
   ↓
CONECTAR
   ↓
INTERACTUAR
   ↓
SIMULAR
   ↓
ANALIZAR

Esta evolución coincide con la identidad del proyecto:
Create · Connect · Evolve.
OmniMerge no pretende únicamente almacenar fichas. Su objetivo final es construir un ecosistema donde recursos definidos libremente por los usuarios puedan organizarse, compartirse y finalmente interactuar dentro de contextos, reglas, universos y torneos.

Entidad: elemento concreto creado por un usuario.
Tipo de Entidad: clasificación general de una Entidad.
Atributo: característica dinámica reutilizable.
Catálogo: conjunto de valores posibles de un Atributo seleccionable.
Elemento de Catálogo: valor individual perteneciente a un Catálogo.
Grupo de Atributos: agrupación visual de diferentes Atributos.
Colección: agrupación de Entidades dentro de la Biblioteca.
Biblioteca: espacio donde un usuario administra sus propios recursos.
Comunidad: espacio donde se descubren recursos publicados por otros usuarios.
Clonación o copia: creación de un recurso independiente basado en otro existente.
Procedencia: referencia que permite conocer de qué recurso se originó una copia.
Hub: centro general desde el cual se accede a los diferentes módulos de OmniMerge.
Soft Delete: eliminación lógica mediante deleted_at.
Policy: componente encargado de comprobar permisos.
Form Request: componente encargado de validar y normalizar solicitudes.
Service: clase dedicada a lógica de negocio compleja.
Eloquent: ORM utilizado por Laravel.
Blade: motor de plantillas utilizado para generar las vistas.
Alpine.js: biblioteca JavaScript ligera utilizada para interacciones de interfaz.
Vite: herramienta utilizada para compilar los recursos frontend.
Universo: futuro contexto donde podrán coexistir e interactuar Entidades.
Torneo: futuro sistema de competencia entre Entidades.
Simulación: futuro proceso automático de interacción basado en características y reglas.
Ranking: futura clasificación basada en resultados e historial.

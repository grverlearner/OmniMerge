1. DATOS GENERALES DEL PROYECTO
Nombre del proyecto: OmniMerge
Tipo de aplicación: Plataforma web multiusuario
Framework backend: Laravel 12
Lenguaje principal: PHP 8.2 o superior
Base de datos: MySQL
Frontend: Blade, Tailwind CSS, Alpine.js y JavaScript
Gestor frontend: Vite
Control de versiones: Git
Repositorio remoto: GitHub
Repositorio: https://github.com/grverlearner/OmniMerge.git

2. DESCRIPCIÓN GENERAL DE OMNIMERGE
OmniMerge es una plataforma web diseñada para permitir que los usuarios creen, organicen, relacionen, reutilicen y posteriormente simulen diferentes tipos de elementos.
La plataforma no se limita únicamente a personajes.
Dentro de OmniMerge una entidad puede representar:
Personajes.
Animales.
Países.
Ciudades.
Objetos.
Vehículos.
Criaturas.
Planetas.
Organizaciones.
Elementos.
Conceptos abstractos.
Colores.
Habilidades.
Lugares.
Cualquier otro elemento definido por el usuario.
La principal característica del sistema es su flexibilidad.
En lugar de imponer una estructura fija como:
Nombre
Edad
Altura
Poder

OmniMerge permite que cada usuario defina sus propios:
Tipos de entidad
Atributos
Opciones
Valores
Grupos
Colecciones

Por ejemplo:
Entidad:
Naruto Uzumaki

Tipo:
Personaje

Atributos:
Anime = Naruto
Elemento = Viento, Fuego
Poder = 92
Puede volar = No

Otro usuario podría crear:
Entidad:
Perú

Tipo:
País

Atributos:
Continente = América
Capital = Lima
Idioma = Español
Población = ...

Por esta razón, OmniMerge se está construyendo como una plataforma general y modular.

    ↓

    ↓

    ↓

    ↓
Regeneración de sesión
    ↓
Redirección


13. CAMBIO IMPORTANTE EN LOGIN
Antes:

 ↓
/dashboard

Ahora:

 ↓
/hub

Para ello se modificó:

El método de inicio de sesión queda conceptualmente:
public function store(
    LoginRequest $request
): RedirectResponse {
    $request->authenticate();

    $request->session()->regenerate();

    return redirect()
        ->route('hub');
}

La razón del cambio es que /dashboard ya no representa todo OmniMerge.
Ahora representa exclusivamente el módulo Biblioteca.

20. CONTROLADOR DEL HUB
Se creó:
app/Http/Controllers/Hub/HubController.php

Comando utilizado:
php artisan make:controller Hub/HubController --invokable

La opción:
--invokable

indica que el controlador tendrá una única acción principal:
__invoke()

Por eso la ruta puede utilizar:
Route::get(
    '/hub',
    HubController::class
);

en lugar de:
[HubController::class, 'index']


21. RESPONSABILIDAD DE HUBCONTROLLER
El controlador calcula estadísticas generales.
Actualmente:
Cantidad de entidades
Cantidad de atributos
Cantidad de colecciones
Cantidad de contenido público

Ejemplo:
$statistics = [
    'entities' => $user
        ->entities()
        ->count(),

    'attributes' => $user
        ->attributes()
        ->count(),

    'collections' => $user
        ->collections()
        ->count(),

    'public_content' => $publicContent,
];


22. CONTENIDO PÚBLICO
Para calcular el contenido público se utilizan diferentes reglas.
Entidades:
visibility = PUBLIC

Colecciones:
visibility = PUBLIC

Atributos:
scope = PUBLIC

Conceptualmente:
$publicContent =
    entidades públicas
    +
    colecciones públicas
    +
    atributos públicos;


23. ACTIVIDAD RECIENTE DEL HUB
También se obtiene actividad de:
Entidades
Atributos
Colecciones

    'icon' => '✦',
    'description' => 'Entidad creada en tu biblioteca.',

Después se combinan:
collect()
    ->concat(...)
    ->concat(...)
    ->concat(...)

y se ordenan por:

de manera descendente.
Finalmente se toman:
6

elementos recientes.

/hub

59. POR QUÉ LOS TESTS DEBEN CAMBIAR
Un test representa el comportamiento esperado del sistema.
Antes:
Login correcto
→ Dashboard

Ahora:
Login correcto
→ Hub

Por tanto, el test antiguo ya no representa la arquitectura actual.
No significa que el código esté incorrecto.
Significa que la especificación cambió.

Usuario A

no debe poder editar:
Entidad de Usuario B

77. LA NAVEGACIÓN NO SUSTITUYE LA AUTORIZACIÓN

Editar

en backend.

81. CONCLUSIÓN
La incorporación del Centro OmniMerge representa una modificación arquitectónica importante.
Antes, el Dashboard existente era considerado el punto principal del sistema.
Ahora se reconoce que ese Dashboard pertenece específicamente al módulo Biblioteca.
El nuevo Hub se convierte en la verdadera entrada a la aplicación autenticada.
La estructura queda claramente dividida:
Página pública
        ↓
Autenticación
        ↓
Centro OmniMerge
        ↓
Módulos

Actualmente los principales módulos son:
Biblioteca
Comunidad
Perfil

y se encuentran preparados visual y conceptualmente los futuros:
Universos
Torneos
Rankings
Simulaciones

Esta arquitectura evita que OmniMerge se convierta en un sistema monolítico desde el punto de vista de navegación y permite que cada gran funcionalidad futura disponga de su propio entorno.
La idea central queda resumida en:
OmniMerge
=
Plataforma


Biblioteca
=
Lugar donde se crean los recursos


Universos
=
Lugar donde esos recursos existirán e interactuarán


Torneos
=
Lugar donde competirán


Comunidad
=
Lugar donde se comparten y descubren


Hub
=
Lugar desde donde se accede a todo

Con esta estructura, OmniMerge dispone de una base más organizada, mantenible y preparada para continuar creciendo.
